# Contributing to olcOS

Useful contributions include reproducible bugs, focused fixes, accessibility
improvements, translations and documentation. For security issues, use
[private reporting](SECURITY.md), not a public issue or pull request.

## Start with the right context

- Read [setup](docs/setup.md), [architecture](docs/architecture.md),
  [build instructions](docs/build.md) and the concise [technical contract](AGENTS.md).
- Search existing public issues before proposing a large change. A small fix
  does not require an issue first; explain the problem in the pull request.
- This repository owns the iOS app and its integration. The separate
  [olcrtc project](https://github.com/openlibrecommunity/olcrtc) owns the upstream
  core; if ownership is unclear, describe the evidence rather than guessing.
- Android, Windows and macOS ideas are welcome as proposals, not descriptions
  of released or currently supported olcOS applications.

## Language and naming

Use **olcOS** for the product and `Hotelk52339/olcos-ios` for this repository.
Keep internal names and existing URI schemes compatible with the
[project configuration](project.yml) and [URI contract](docs/uri.md).

English is preferred for identifiers, engineering comments and commit messages.
Russian, English and French are welcome in issues; the README offers separate
Russian and English editions through an upfront language selector.
User-facing text belongs in the localization system, with matching RU/EN/FR
entries and format placeholders, not hardcoded strings. Add or change strings
with `python3 scripts/dev/l10n.py add|set|remove KEY --en … --ru … --fr …` and
run `python3 scripts/dev/l10n.py check` before committing.
The extension has separate localized resources. [Localization implementation](App/Localization/L10n.swift) ·
[project resources](project.yml).

## Make a focused change

1. Work on a branch and limit the patch to one reviewable purpose.
2. Add or update tests for changed behavior. Include failure and cancellation
   paths when touching lifecycle, routing, imports or persistence.
3. Update documentation if the support boundary or user flow changes.
4. Inspect the diff for secrets, generated output and unrelated changes.
5. Open a pull request using the template and state what was actually verified.

Public task IDs are optional references, not mandatory source markers. There
is no requirement to preserve old code as commented-out replacements. Explain
the *reason* for a non-obvious decision and let Git retain ordinary history.

### Commits

Use factual Conventional Commits:

```text
fix(ssh): reject changed host keys without replacing saved trust
test(vpn): cover cancellation during profile cleanup
docs(setup): explain proxy-only routing
```

Do not put AI attribution, prompt text, conversation references or “requested by
the user” in commit subjects/bodies. Describe the change and its rationale.
Commits, pushes, tags and releases follow the repository owner's authorization;
do not publish without it.

SSH trust is automatic on first use, bound to the original host and port.
Preserve comparisons on later connections, changed-key rejection and explicit
confirmation before resetting trust. Do not add a mandatory fingerprint-entry
step or claim the first connection was independently verified.
[SSH trust contract](App/Core/SSHHostKeyVerification.swift) · [security policy](SECURITY.md).

### Generated files and versions

`project.yml` is the source for the Xcode project and configured plists;
`App/Mobile.xcframework` is generated by the framework scripts.
Do not hand-edit generated artifacts to mask a source problem.
[Project](project.yml) · [build script](scripts/build-framework.sh).

Release identity for olcOS 2.0 is version `2.0`, build `2`, tag `v2.0.2`.
The release owner coordinates subsequent build/version changes; contributors
should not race the build counter or bump it for each pull request.
Preserve bundle IDs, storage keys and URI compatibility.

## Server-script parity is a special contract

`scripts/srv.sh` is a locally adapted copy of the pinned upstream `install.sh`.
The checker requires local changes inside `# boc olcrtc-ios` /
`# eoc olcrtc-ios` blocks and deliberately rejected upstream lines inside
`# boc olcrtc-ios-rejected: <reason>` blocks; preserve those markers and run:
[Parity implementation](scripts/parity_check.py).

```bash
python3 scripts/parity_check.py
```

Do not apply this marker convention to unrelated app code. When changing the
upstream pin, review script parity, framework shims, carrier expectations and
generated bindings together rather than disabling checks.
The add-carrier and key-rotation scripts also have cross-script contracts.
[Script tests](Tests/ServerScriptParityTests.swift) ·
[add-carrier tests](Tests/AddCarrierScriptTests.swift) ·
[rotation tests](Tests/RotateKeyScriptTests.swift).

## Show verification, not confidence

For each check, include **PASS / FAIL / NOT RUN / NOT APPLICABLE**, the command,
tool versions or OS, and relevant output or a CI run URL. Never check “tests
pass” because tests exist or because a previous revision passed.

Use [build/test commands](docs/build.md). Simulator testing does not validate a
live NetworkExtension tunnel, device signing, lock-screen/background behavior
or physical haptics; those require appropriate native-device evidence.
For UI changes, label concepts as concepts and actual screenshots with the
device/simulator, OS and build used.

Review RU/EN/FR, VoiceOver/Dynamic Type as applicable, Reduce Motion and both
light/dark appearances when altering the interface. Keep the hero picture (beam
and stone wall) free of invented telemetry: it may follow measured throughput,
but no invented packet rates, printed speed results or continuously firing haptics.
[Motion and haptic policy](App/Views/SignalWaveform.swift).

## Keep reports safe and preserve attribution

Use synthetic hosts such as `vps.example.org` and reserved example addresses.
Never attach real connection links, private keys, passwords, tokens, account
cookies or unsanitized logs. Redaction is an aid, not a guarantee; inspect each
attachment yourself. [Security policy](SECURITY.md) · [log pipeline](App/Services/LogStore.swift).

Preserve the project [LICENSE](LICENSE) and applicable dependency licenses when
distributing the software. Upstream olcrtc retains its own
[WTFPL license](olcrtc-upstream/LICENSE).
